## 1. Why this story exists

### 1.1 The conditional expression

A Domino table write `T[k] <- e`, where `e : Maybe(V)` is not syntactically `Some(_)` or `None`,
is translated today to one assignment with a conditional expression
(`translate_table_write`, `src/writers/easycrypt/package.rs:961`; overview §3 "Tables", first
design session, 2026-09-16):

```
T <- if e = None then rem T k else T.[k <- oget e];
```

This is sound. `oget` is evaluated only when `e <> None`, and the expression is pure. It agrees
with the debugger, which models the write as one `(store T k e)`. The cause is that EasyCrypt's
`fmap` has no operator that sets a key to an option (`FMap.ec:15,186`: only `_.[_ <- _]` and
`rem`).

But the owner found the line surprising, and it hides a real decision:

- The listing and the debugger show one line where there are two cases (store or remove).
  Lockstep cannot decide the case, so a determined case does not become simpler.
- After `wp`, the leaf goal carries the whole conditional map term. `smt` must reason about it
  inside the relation's quantifiers. The base hints have no lemma for `rem`
  (`BASE_SMT_LEMMAS = ["get_setE", "mem_set", "emptyE"]`, `src/easycrypt/tactics/driver.rs:409`).
- The hand-written proof (`~/Research/ec4whs/simple`) never uses `rem`. It writes
  `fresh_map.[ctr_] <- oget honesty_map.[kid]` and relies on the path or the invariant.

### 1.2 Where it occurs, measured

Full4WHS export (`~/Research/ec4whs/autogenerated/Full4WHS/`) has **7** such writes, of two kinds:

| Domino (`example-projects/4WHS/packages/KX.pkg.ssp`) | Oracle | Packages |
|---|---|---|
| `LTK[kid_] <- ltk`, in the `else` of `if (ltk == None)` | `NewKey` | `KX`, `KX_nochecks`, `KX_nokey`, `PRF` |
| `Fresh[ctr_] <- H[kid]`, after `assert not (LTK[kid] == None)` | `NewSession` | `KX`, `KX_nochecks`, `KX_nokey` |

In `NewKey` the path already proves `ltk <> None`. In `NewSession` only the invariant can tell
if `H[kid]` is `Some`.

From the transcripts of 2026-10-08 (all 9 hops; answers are capped, so `rem` counts are lower
bounds):

- **2 of 840** admits have `rem` in the goal. Both are in H6_1_0 ~ H6_1_1 `NewKey`.
- **27** successful `smt` calls have `rem` in the goal.
- Each `NewKey`/`NewSession` joint tree has **4** terminals, in every hop.

Baseline of the oracles that §5 measures:

| Hop | Oracle | Sentences | Time | Admits |
|---|---|---|---|---|
| H2_1 ~ H3_0 | `NewKey` | 11 | 9 s | 0 |
| H2_1 ~ H3_0 | `NewSession` | 104 | 231 s | 0 |

The expected gain in admits is small. The main gain is a listing and a joint tree that show the
two cases, and the hand-written line where the case is known.

### 1.3 Research

- EasyCrypt's `simplify if` tactic does the **opposite** conversion (a statement `if` to a
  conditional expression), because `wp` over many undecided `if`s grows exponentially
  (`refman/refman/_sources/tactics/simplify-if.rst.txt`). In our design lockstep decides each
  branch before the leaf, so `wp` sees only branches that story 64 step 1 cannot decide. If a
  project shows that blow-up, a proof can still apply `simplify if` to the branch.
- Symbolic execution has the same trade-off as **state merging** against **path splitting**:
  merged `ite` terms give fewer paths but harder solver queries
  (Kuznetsov et al., PLDI 2012; Avgerinos et al., "Veritesting", ICSE 2014; Baldoni et al.,
  "A Survey of Symbolic Execution Techniques", arXiv 1610.00502). We split, because each case
  then has simple map terms, and a determined case costs one decision.
- OCaml's `Map.update` (an option result removes the key) is the operator `fmap` does not have.
  We do not add it (ADR 0015, rejected options).

Vocabulary (`CONTEXT.md`, updated by this story): **Table write**. Also **Exit guard**,
**Decision point**, **Synchronized branch**.

## 3. Work to do

### 3.1 The rewrite (in `guard_unwraps`)

In `UnwrapGuards::block`, a statement `T[k] <- e` (`Pattern::Table`,
`AssignmentRhs::Expression(e)`) where `e` is neither `Some(_)` nor `None` becomes:

- **if `facts` contains `e`:** `T[k] <- Some(Unwrap(e))`. No branch.
- **else:**

  ```
  if (not (e == None)) {
      T[k] <- Some(Unwrap(e))
  } else {
      T[k] <- None
  }
  ```

  Build the condition with the existing `is_some` helper, so `some_test` reads it. Use the
  write's span for the new `if` and both statements.

Then the write kills the facts that read `T`, as today.

Both branches are `Term::Never`, so the lowering continues after the `if` with no done-flag guard
(story 16 §3.3, last case). `e` appears twice, as it does in the conditional expression today.
No temporary is bound.

### 3.2 Facts from the else-branch of a `None` test

Extend `some_test` (or add a sibling) so that `if (e == None) { A } else { B }` gives the fact
`e` inside `B`. The rest of the rules do not change: a fact never leaves its block, and a write to
what `e` reads kills it.

This also lets rule 2 drop an unwrap guard inside such an else-branch. That is correct, and it
changes other goldens.

Extend `every_unwrap_is_guarded` to accept "inside the else-branch of `if (e == None)`".

### 3.3 The writer

`translate_table_write`'s general arm (`package.rs:990-1017`) becomes
`unreachable!("easycryptify rewrites every table write whose value is not Some or None (story 70)")`.
The `Some(_)` and `None` arms produce the two lines:

```
if (!(e = None)) { T.[k] <- oget e; } else { T <- rem T k; }
```

Remove `EcExpr::If` from `ast.rs` and `render.rs` only if nothing else uses it.
`invariant.rs` uses it, so it probably stays.

### 3.4 Lockstep, alignment, tactics

No change. The new `if` is a plain `InlStmt::Branch` with no marker. Lockstep classifies it with
its normal rules: determined (`rcondt`/`rcondf`), synchronized (`if`), or split (`if{1}`/`if{2}`).
EasyCrypt's `inline` output has the same `if`, so the decision skeletons agree.

### 3.5 Hints

`BASE_SMT_LEMMAS` becomes `["get_setE", "mem_set", "remE", "mem_rem", "emptyE"]`. `remE` and
`mem_rem` are the read and membership lemmas of `rem`, as `get_setE` and `mem_set` are for
`_.[_ <- _]` (`FMap.ec:199,207`). Update any test or golden that spells the hint sentence.

## 5. How to verify

```bash
cd example-projects/4WHS
# translation: the conditional expression is gone
$D --out <out> easycrypt export --theorem Full4WHS
grep -c 'then rem' <out>/Pkg_*.ec          # expect 0
# lockstep on every hop: terminals and verdicts of NewKey / NewSession
$D easycrypt debug --theorem Full4WHS --proofstep <N> --oracle NewKey   # and NewSession
# alignment on the testing ladder
$D easycrypt check-alignment --theorem Full4WHS
# tactics, only the two oracles, on the three hops whose transcripts have `rem`
$D easycrypt prove --theorem Full4WHS --proofstep <N> --oracle NewKey   # then NewSession
```

`<N>` is the proofstep number of each hop (`domino proofsteps`). For the tactics runs, use the
proofsteps of H2_1 ~ H3_0, H5 ~ H6_0 and H6_1_0 ~ H6_1_1.

The implementation report gives:

1. The number of conditional table writes before (7) and after (0), and how many became a plain
   write and how many a branch.
2. For each of the 9 hops: the terminals of `NewKey`/`NewSession` before (4) and after, and how
   lockstep classified the new branch (determined, synchronized, split).
3. For the six oracle runs: sentences, time and admits before (§1.2 table) and after.
4. The admitted parts whose goal has `rem` after this story. This is the evidence that story 66

## 6. Notes / risks

- **Leaf count.** An undetermined write that is not synchronized splits into up to 4 joint cases
  (infeasible ones pruned). Several such writes in one oracle multiply. Full4WHS has at most one
  for each oracle. If a project shows a blow-up, report it; do not go back to the conditional
  expression without a new decision (ADR 0015).
- **Story 64's leaf rule** ("any other `if`: try `rcondf` first") applies only when this branch is
  still open at a leaf. Lockstep normally decides it earlier.
- **The Domino listing** (`DebugTransform`, no `easycryptify`) does not change. It keeps one
  table-write line.
- **Story 66 does not change.** Its "updated map" is still only `_.[_ <- _]`.

## 7. Rejected alternatives

Recorded in ADR 0015, with reasons:

- Keep the conditional expression and only add hints.
- A helper operator `set_opt T k e` in `Types.ec`, with a generated, proved lemma.
- A static `if` only where translation can decide it (only lockstep knows the path and the
  invariant).
- The rule in the writer and the lowering separately (two copies of one rule, the bug class of
  story 53); a separate transform after `easycryptify` (an extra seam, the facts recomputed).
- Facts only as today (`NewKey` would keep a determined `if`); never leave out the `if`.
- The `None` test first (`if (e = None) { rem } else { set }`).
- A marked branch kind (`TableWriteGuard`) for lockstep and the viewer.
- `remE` only; hints chosen by scanning the goal (more answer bytes, story 61); hints left to
  `ssp.toml`.
- Story 66 treating `rem m k` as an updated map now (owner: wait for §5 item 4).
- Tactics runs on all hops (the other oracles have no table-write change).
