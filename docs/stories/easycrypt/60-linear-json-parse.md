# Story 60 — Domino parses an answer in linear time, and the report shows parse time

**Epic:** EasyCrypt Export — read `docs/stories/easycrypt/00-overview.md` first.
**Branch:** `amir/easycrypt-export`
**Depends on:** 54 (`domino-json/2`), 57 (time by role).
**Blocks:** 61.

A **speed** story, Domino only. The sentences that a run sends, the protocol and the proof files do
not change.

---

## 1. Why this story exists

In the Full4WHS runs of 2026-10-08 (all nine hops, 29.0 h of wall time), 11.6 h is "rest of round
trip": time that is neither EasyCrypt's tactic time nor its serialization. In H6_1_1 ~ H7_0 this
part (5.3 h) is larger than the proving time (4.8 h). The notes
`~/Research/ec4whs/autogenerated/Full4WHS/Proof_Statistics.md` ("Serialization and parsing") and
`Eq_H2_1_H3_0_Reproved.md` §1 found the cause:

`src/easycrypt/json.rs` reads `Form.args` through `one_or_many`, a `#[serde(untagged)] enum
OneOrMany { Many(Vec<Form>), One(Box<Form>) }`. Serde copies an untagged value into a generic
`Content` tree before it tries each variant. A `Form` holds `args`, which hold `Form`s, so each
level copies its whole subtree again. A node at depth *d* is copied about *d* times: O(n·d), which
is close to O(n²) for these goals.

Measured on a captured 7.1 MB answer: 1.87 s (release) / 2.99 s (debug) with the current parser;
0.05 s / 0.15 s with a visitor.

The report cannot show this today, because nobody measures the parse.

Vocabulary (`CONTEXT.md`): **Front goal**, **Sentence role**, **EasyCrypt transcript**.

## 2. Inherited from earlier stories

- **Story 54:** `parse_response` (`json.rs`) parses one answer line on the reader thread of the
  session (`session.rs:291`), with the recursion limit off.
- **Story 55:** each answer has `timing.tactic_ms` and `timing.serialize_ms`.
- **Story 57:** the report has a time-by-role table for each oracle, and an `EasyCrypt:` line with
  the sums of the timing fields.

## 3. Work to do

### 3.1 The visitor

Replace the untagged enum in `one_or_many` with a hand-written `Deserialize` visitor:
`visit_seq` reads a list of `Form`s, and `visit_map` reads one `Form` into a list of one. The first
token decides the variant, so nothing is buffered, copied or tried again. Keep the function's
signature; `Form` does not change.

### 3.2 Parse time

- The reader thread measures the time of `parse_response` for each answer (`parse_ms`).
- The transcript record gets `parse_ms` next to `ms`.
- The report's `EasyCrypt:` line for each oracle gets `parse` after `serialize`:
  `… serialize 2m 42s, Domino parse 0m 04s`.
- `ms` stays the full round trip, so the time-by-role table still sums to the oracle's EasyCrypt
  time.

### 3.3 Rejected alternatives

- **The fork always sends `args` as a list.** Rejected: a protocol change for a problem that is
  only Domino's. Story 61 bumps the protocol for other reasons and may do this too, but this story
  must not wait for it.
- **Change the build profile** (`[profile.dev] opt-level`). Not needed: with the visitor, a debug
  build parses 7 MB in about 0.15 s.

## 4. Acceptance criteria

- [ ] A test builds a formula nested 2,000 levels deep (a chain of `/\`), parses it, and checks

      be generous enough not to fail on a slow CI machine.
- [ ] A test parses an answer with `args` as a single object (the `pr` case) and as a list.

      "rest of round trip" before (the 2026-10-08 numbers in `Proof_Statistics.md`) and after.
