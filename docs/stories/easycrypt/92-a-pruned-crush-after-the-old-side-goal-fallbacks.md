## 1. Why this story exists

After story 86, the 4WHS run (`ec4whs/autogenerated/Full4WHS/Proof_Statistics.md`, commit
`bd8901f`) still has 62 side-goal admits, all `domino-verified-ec-failed`:

| Kind | Hops | Side-invariant lemmas | Total |
|---|---|---|---|
| `branch-condition` (two-sided `if.`) | 41 | 0 | 41 |
| `side-goal` (`rcondt` / `rcondf`) | 17 | 4 | 21 |

### 1.1 What makes `smt` fail (experiments of 2026-10-22)

Each admit was tested alone on a reduced copy of its file (`easycrypt llm -upto`). Three facts:

1. **More time does not help.** `smt timeout=20.` closes none of the goals that fail at the default
   timeout.
2. **The `side_inv_<C>` premises make `smt` fail**, even when they stay folded and even when they are
   only hypotheses in the context.
3. **The same facts close the goal as goal premises, and fail as hypotheses.** A standalone lemma
   with the same goal closes either way. The effect occurs only inside the real proof.

This agrees with the literature: the SHAKE paper (Zhou, Bosamiya, Li, Heule, Parno, FMCAD 2024)
finds that irrelevant context causes 78 % of SMT instability in program-verification queries, and that
pruning it makes cvc5 29–41 % more stable.

The crush of story 86 (`move=> /> <mems> *; smt().`) has both problems: `*` puts every premise in
the context, the two `side_inv`s included.

### 1.2 The recipe that closes them

`move=> /> &1 &2.` (or `&hr`), read the goal, then name each binder and premise, give `_` to each
`side_inv_*` premise, and move the others back into the goal:

```
move=> /> &1 &2 h0 h1 h2 h3 _ _ h6 h7; move: h0 h1 h2 h3 h6 h7; smt().
```

(`Eq_H5_H6_0_Test.ec:128`.) On the 62 admits this closed **40 of 41 `branch-condition`** and **3 of
21 `side-goal`** (`Eq_H5_H6_0_Reveal.ec:140`, `Eq_H5_H6_0_Test.ec:186`, `Eq_H6_1_1_H7_0_Send3.ec:770`).
Each of the 43 dropped two premises. The 18 patched files compiled whole with `-timeout 10`.

The goal after `move=> /> <mems>.` is small: 3.0–12 KB (median 7.5 KB) for all 62 goals, not the
0.2–3 MB of a whole premise that ADR 0012 avoids.

## 2. What goes wrong

`fallbacks()` (`driver.rs`) has no step that keeps the facts of the premise and drops the side
invariants. The crush keeps everything in the context; fallbacks 3 and 5 keep the whole premise as
one hypothesis and unfold `inv` in it.

`*` cannot be the base of a fix: after `move=> /> &1 &2 *.` EasyCrypt names each hypothesis `_`, and
no later tactic can clear or revert it. The premises must be named, so Domino must read their list.

## 3. What to build

### 3.1 The new fallback sequence

| # | Fallback | Today |
|---|---|---|
| 1 | crush | 1 |
| 2 | `smt().` with the premise unfolded (`try_with_premise("smt().")`) | 3 |
| 3 | `smt(<hints>).` | 4 |
| 4 | **pruned crush** (§3.2) | new |

Old fallbacks 2 and 5 are removed. `FALLBACKS` becomes 4. The pruned crush is last, so it gets only
the goals that the old fallbacks leave: no goal that closes today can get an admit.

### 3.2 The pruned crush

1. Take a snapshot. Send `move=> /> <mems>.` with `Want::Full`. If EasyCrypt refuses, roll back and
   return `false`. If the goal count drops, the goal is closed: return `true`.
2. Walk the front goal's conclusion in order, with `goals::as_forall` and `goals::as_implication`:
   - each binder gets a fresh name `x<i>`; a `forall` **between two premises** is a binder too (the
     first prototype missed this);
   - each premise whose head operator is in `drop_ops` (§3.3) gets `_`;
   - each other premise gets a fresh name `h<i>`.
3. Send `move=> <names>; move: <kept>; smt().`, where `<kept>` is every named binder and premise in
   intro order. Without kept names, send `move=> <names>; smt().`
4. If the goal count did not drop, roll back to the snapshot (both sentences) and return `false`.

The sentence comes from a pure function, `pruned_crush_sentence(concl, drop_ops) -> Option<String>`
(`None`: the goal has no premise). Its tests need no EasyCrypt.

### 3.3 The new input `drop_ops`

`Prover` gets `drop_ops: &'a [String]`, next to `unfold_ops`: the qualified names of the side-invariant
operators in the precondition. `mod.rs` (where it builds `unfold_ops`) fills it:

| Job | `drop_ops` |
|---|---|
| equivalence | `Comp_<C>.side_inv_<C>` of each of the two compositions that has side invariants |
| side invariants | `Comp_<C>.side_inv_<C>` (the first item of `unfold_ops`) |
| package invariants | empty |

The name comes from the same function as the precondition's `side_inv` application
(`proof.rs`, `invariant::side_inv_op_name` with the composition's theory). Do not match a name
pattern such as `side_inv_` in the driver.

### 3.4 The live page and the transcript

Role `SideGoalFallback(4)`; the live page shows `pruned crush`. Both sentences of the pruned crush
carry this role.

## 4. Rejected alternatives

- **Pruned crush first, in place of the crush.** Faster only if the pruned crush closes what the crush
  and `smt(<hints>)` close today; not measured. With the pruned crush last, "no new admit" holds by
  construction. A goal that reaches it pays about 20 s of failed old fallbacks; about 60 goals in all
  hops, about 20 minutes per full run.
- **Keep old fallbacks 2 and 5.** 1 closing in 966 episodes for about 12 minutes of failed tries.
- **Introduce one premise at a time** (`move=> h.` with `Want::Head` in a loop, clear the `side_inv`
  ones). Small answers, but 10–25 round trips per side goal and a loop with its own stop condition
  inside the rollback logic.
- **Take the premise list from the precondition Domino wrote.** `/>` substitutes and opens
  existentials; the list after it cannot be predicted.
- **`side_inv_<C>` as `op [opaque]`.** Story 86 §1.1: no help. And folded `side_inv` premises still make
  `smt` fail (§1.1).
- **Recognise a `side_inv` premise by a name pattern in the driver.** A hidden coupling to the naming
  rule: a renamed operator makes the drop stop without an error.
- **A longer `smt` timeout.** §1.1, fact 1.

## 5. Tests first

- [ ] `pruned_crush_sentence`: `forall (a b : int), A => Comp_H5.side_inv_H5 r => B => forall z, C =>
      D` with `drop_ops = [Comp_H5.side_inv_H5]` → `move=> a0 b0 h0 _ h1 z0 h2; move: a0 b0 h0 h1 z0
      h2; smt().` (the name scheme is free; the names are fresh against the goal, and `z` is
      reverted in its place between the premises).
- [ ] The same goal with empty `drop_ops`: nothing dropped, all reverted.
- [ ] A `side_inv` premise in parentheses or applied to a record literal: still dropped.
- [ ] A goal without a premise → `None`; a goal whose only premises are dropped → `move=> …; smt().`
      without `move:`.
- [ ] `drop_ops` of an equivalence job (both sides with side invariants) holds both names, and each
      name occurs in the generated precondition text (locks §3.3).
- [ ] Sequence, scripted session (as
      `fallbacks_and_admits_ask_for_status_and_the_opening_for_the_head`, `tests.rs`), every try
      failing: `auto => /#.`, crush, `move => &1 &2 hpre.` + `rewrite … in hpre.` + `smt().`,
      `smt(<hints>).`, `move=> /> &1 &2.` (asked `Full`), the pruned sentence, then the admit. Old
      fallbacks 2 and 5 are not sent.
- [ ] The pruned sentence closes the goal → no admit, nothing else sent.
- [ ] The pruned sentence fails → both sentences rolled back, then the admit with the same reason as
      today.
