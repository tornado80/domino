# Story 88 — Implementation report: a goal formula keeps every sub-formula

Rust only. The §7 questions use the recommended answers (see "Open questions"). No ADR.
Story 86 replaced `mentions_op` with `goals::may_mention_op`. Where the spec names
`mentions_op`, this report means `may_mention_op`.

## What changed

### `Form` reads every sub-formula (`src/easycrypt/json.rs`)

- `Form` has the new fields of §3.1, all `#[serde(default)]`: `arg`, `index` (`proj`), `items`
  (`tuple`), `cond`, `then_form` (`then`), `else_form` (`else`) (`if`), `scrutinee`, `branches`
  (`match`), `bound` (`let`), `event` (`pr`) and `bd` (`phoareS`, `phoareF`). `exn` stays
  unread.
- The doc comment of `Form` tells which field each kind fills, and points to
  `easycrypt/doc/json-output.md`, "FORM".
- New `Form::children`: the direct sub-formulas in the schema order of §3.2 (`head`, `args`,
  `items`, `arg`, `cond`, `then`, `else`, `scrutinee`, `branches`, `bound`, `body`, `event`,
  `bd`, `pre`, `post`). A stub has none.

### The walks use `Form::children` (`src/easycrypt/tactics/goals.rs`)

- `may_mention_op` uses `form.children()`. The private `goals::children` (head, args, body, pre,
  post only) is removed.
- `collect_key_pairs` (`key_pairs`, part fallback 4) uses `form.children()` in place of its own
  chain. Thus a read under a projection, an `if`, a tuple, a `let` or a `match` gives its key
  pair, and part fallback 4 sends the `case` on the parts of §1.

### Fixture (`testdata/easycrypt/story88/`)

- `each_formula_kind_full.json`: the `full` answer to the lemma
  `story88 (x : int * bool) (y : int) : (if x.`2 then (x, y).`1.`1 else let z = y + 1 in z) =
  (match Some y with | None => 0 | Some w => w end)`. It has `proj`, `tuple`, `if`, `match` and
  `let` nodes (2706 bytes).
- `requests.jsonl`: the two requests that made it. It was recorded with
  `easycrypt/_build/default/src/ec.exe cli -json` (the JSON branch binary; the spec says
  `easycrypt llm`, which is the same JSON mode), with `ulimit -v 6000000` and `timeout 300`.

## Deviations from the spec

- The fixture was recorded with `ec.exe cli -json` (the binary of the JSON branch), not with a
  command named `easycrypt llm`.
- The §3.3 lemma has no `pr` node: the `Pr[...]` form needs a module and a procedure, which
  makes the lemma bigger. The unit tests do not cover `event` and `bd` either; the schema check
  covers every field that the fixture has.
