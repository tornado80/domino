## What was built

- **`part_fallback_order(judgement, premises)`** (`driver.rs`): a pure function that returns
  `[Crush, Smt, Hints]` for a `Reduction` with premises, `[Smt, Hints, Crush]` for the other
  judgements, and `[Smt, Hints]` with no premises. `atom` maps it to sentences. `retry_close`
  is unchanged: it runs after the last fallback times out, and with premises its sentence is
  the crush with the longer timeout.
- **`quick_closes_before(head)`** (`reduction_walk.rs`): an exhaustive match. It is true for
  `Leaf`, `Branches`, `Samplings` and `Mismatch`, and false for `AssumptionGuard`, `TailBranch`
  and `ExitGuards`. `walk` lost its `arm_start` flag. It reads the heads (`full_front`,
  `classify`), then tries the quick close if `quick_closes_before` says so, then takes the step.
  `leaf` is gone, because `Leaf` calls `leaf_of` directly.
- `docs/proving-algorithm.md` §7.2 (the reduction part order) and §10.1 (the walk without
  `arm_start`).

## Deviations

1. **The `ExitGuards` fallback to `if.` also tries the quick close.** When a side is not decided,
   both sides are undone and the guards are split by `if.`. That is a fork, so the quick close
   comes before it, following the rule of §3.2 item 7 that the quick close comes before every
   point where the walk forks. No unit test covers it. It is an inline call in `exit_guards`.
2. **The mismatch test runs with the quick close off.** With the quick close before a
   `Mismatch`, the fixture's `if (true) { }` is closed by `auto => /#.`, so the admit is gone,
   which is what §3.2 item 6 is for. The test now checks the walk's mismatch handling with
   `quick_close: false`.
3. **The `reduction-two-calls` structure checks moved to its no-quick-close run.** With the
   quick close on, the arm closes after the first `rcondt{2}`, so the checks for at least two
   `rcondt{2}` and for `seq 1 1` now apply to the second run of the same test.

## Follow-ups

- On hop 12 the crush closed every part. `smt().` and `smt(<hints>).` after it are kept only as
  a safety net (§6). A run of hops 3 and 5 would show whether that holds more widely.
- The fork quick closes that fail (269, 441 s) are now the largest wasted cost. The 2 s cap is
  shared with the equivalence algorithm, so any change to it needs the owner.
- `crush_first` holds trivially when a fixture has no part fallbacks. A small fixture with a
  reduction leaf part that `/>` alone does not close would make it bite.
- The CRAP gate cannot run in this sandbox (bwrap).
