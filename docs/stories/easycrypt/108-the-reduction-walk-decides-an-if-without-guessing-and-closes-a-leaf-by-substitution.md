## 1. Why this story exists

Story 107 closed all 12 oracle lemmas of `Red_H7_1_H7_0` with no admit. But the walk spent 7966 s of
EasyCrypt time on them, about the same as the blind walk (8309 s). `Send4` was 54% slower than the
blind walk. The walk knows the shape of the code, so it should not need that time.

Most of the time goes to three things that the walk can avoid:

1. **A wrong guess at an `if`.** At an exit guard, the walk tries `rcondf{i} ^if; 1: auto => />.`,
   then `rcondf … /#`, then `rcondt … />`. When the branch is taken, `/>` leaves the `rcondf` side
   goal open (undone), and `/#` then fails after about 4.5 s before `rcondt … />` succeeds. Each
   side guesses on its own, though both sides run the same code.
2. **An `sp` before each head.** The walk sends `sp k l.` before it classifies each pair of heads,
   so `#pre` grows a new existential at every `rcond`. The equivalence algorithm sends `rcondt{i}
   ^if` with no `sp` in front (`driver.rs`, the comment of `step_node`): `sp` comes only before a
   two-sided step.
3. **A leaf split into about 22 parts.** The leaf procedure unfolds the invariant in `hpre` and
   splits the goal into its conjuncts. Each part (`ec_result{1} = ec_result{2}`,
   `Comp_H7.Game_H7.abort_flag{1} = Red_H7_1_H7_0.abort_flag{2}`, …) gets `smt().` with an 18 kB
   context, about 2.9 s each. The reduction's invariant is equality of the two sides' states, so
   substitution closes almost all of these parts at once.

## 3. What to build

### 3.1 Decide an `if` with the cheap closer first

1. **`decide` order.** For a decision on side `i`, try `/>` in both directions before any `/#`:
   `rcondf{i} … />`, `rcondt{i} … />`, then `rcondf{i} … /#`, `rcondt{i} … /#`. The first direction
   of each pair is still the one `exit_decisions` predicts. A sentence counts as accepted only when
   its side goal is closed, as now.
2. **Exit guards: the right side repeats the left side's decision.** Both sides run the same code,
   so the right exit guard goes the same way. After side 1 is decided with `d`, side 2 tries `d` first
   (`/>`, then `/#`), and the other direction only if both fail.
3. **Tail branch:** the same order as item 1 on side 2 (`rcondf/>`, `rcondt/>`, `rcondf/#`,
   `rcondt/#`), then the `rcondt{2} ^if.` step as now.

### 3.2 No `sp` before an `rcond`

4. **Classify the heads without `sp`.** The head of a side is its first statement that is not an
   assignment. `classify` gets the two programs with their leading assignments skipped. `walk` no
   longer sends `sp_front` before it classifies.
5. **`sp` only before a two-sided step**, as the equivalence algorithm does: before `if.` (Branches)
   and before `seq 1 1` (Samplings), `sp k l.` with the counts of the leading assignments. An
   `rcond` (assumption guard, tail branch, exit guard) is sent with no `sp` in front: `^if` finds the
   first `if`, and the side goal reasons about the assignments before it. A leaf needs no `sp`: its
   `auto` takes the assignments.
6. **Story 104's check** (`sampled_in_pre`) reads `#pre` after the `sp` of the sampling, as now: it
   runs after that `sp`, just before `seq 1 1`.

### 3.3 A reduction leaf is closed by substitution

7. **For `Judgement::Reduction` only:** after `auto => &1 &2 hpre.` and the unfolding of the invariant
   in `hpre`, send `move: hpre => />.`. It substitutes the equalities of the two states and closes
   the parts that become trivial. `open_part` then opens what is left, as now. If `move: hpre => />.`
   is refused, undo it and go on as now.
8. **Equivalences, side invariants and package invariants do not change.** Their leaf keeps `hpre`,
   because Domino's verdict and the fallback sequence (crush, pruned crush, invariant selection) work
   on its parts.
9. The quick close and its 2 s timeout do not change in this story.

## 6. Rejected alternatives

- **Change the shared leaf procedure for every judgement.** An equivalence invariant relates tables
  and side invariants, and its parts go through Domino's verdict and the tuned fallback sequence
  (stories 86–93). Substitution brings no clear gain there, and it would change the equivalence
  proofs. Rejected by the owner, 2026-11-13.
- **Raise the quick-close timeout.** It would close these leaves too (1.1 s alone), but the margin
  depends on the machine's load and on `--jobs`, and the timeout is shared with the equivalence
  algorithm. Whether equivalences miss quick closes the same way is a separate question.
- **Do all `rcond`s first, then all `sp`s.** The same result as item 5 for the `rcond`s; item 5 also
  covers `if.` and `seq`, which need the heads in place.
